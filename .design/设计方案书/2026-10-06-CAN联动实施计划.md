# CAN v3 双向联调实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不使能电机的条件下，验证 Jetson Orin 与 C30D 下位机通过经典 CAN v3 双向收发。

**Architecture:** 下位机使用当前 `main` 的 R21 固件，通过 bxCAN 1 Mbps 接收 `0x100` 禁用零速命令，并周期发送 `0x200` 速度反馈和 `0x230` 节点信息。Orin 使用已提交的 `rak_can_driver` SocketCAN 节点，固定 `initial_enable=false`；先验证代码和依赖，再启动 `can0`，最后并行观察 CAN 帧与 ROS 反馈。全程不发 `START`、不发使能位为 1 的命令、不发非零速度。

**Tech Stack:** STM32F407 HAL/CubeMX、CAN v3、Jetson Orin Nano、Linux SocketCAN、ROS 2 Jazzy、python-can、pytest。

---

## 文件职责

- `Core/Src/app_can.c`：CAN v3 接收、协议分发及 `0x200`、`0x230` 周期发送；本轮只验证，不预设需要改动。
- `Core/Src/can.c`、`Core/Src/main.c`、`vehical_rak_chassis.ioc`：CubeMX 生成的 CAN1 外设配置与启动顺序；本轮不手改外设初始化。
- `tools/can_check.py`、`tools/cubemx_lint.sh`：下位机协议与 CubeMX 边界门禁。
- `src/rak_can_driver/rak_can_driver/chassis_node.py`：Orin SocketCAN 节点，默认不使能并以 100 Hz 发送 `0x100`。
- `src/rak_can_driver/rak_can_driver/protocol.py`、`src/rak_can_driver/test/test_protocol.py`：上位机 CAN v3 编解码和 golden vector 测试。
- `.design/设计方案书/2026-10-06-CAN联动设计方案.md`：本次联调的已确认设计边界。

本轮不实现 `0x201 CHASSIS_DIAG`：R21 当前没有发送此帧，上位机虽支持解码，但底盘状态位和故障码映射尚未形成明确合同。它不阻塞 `0x100` 与 `0x200`/`0x230` 的双向基础验证。

## Task 5：执行禁用零速双向实链路验证

**Files:** 无源文件改动；Orin 运行 CAN 节点和观察命令。

- [ ] **Step 1：确认底盘周期帧到达 Orin**

运行：`ssh orin 'timeout --preserve-status --signal=INT 5s candump -L can0,200:7FF,230:7FF'`

预期：收到 8 字节 CAN v3 `0x200` 与 `0x230` 帧，CRC 解码正确；`0x230` 的协议版本和硬件版本字段分别为 3、1。若未收到，停止，不继续向底盘发送。

- [ ] **Step 2：启动禁用状态的 SocketCAN 节点**

在 Orin 加载 ROS 2 Jazzy 后运行：

```bash
ssh orin 'source /opt/ros/jazzy/setup.bash && PYTHONPATH=$HOME/rak/src/rak_can_driver${PYTHONPATH:+:$PYTHONPATH} timeout --preserve-status --signal=INT 15s python3 -m rak_can_driver.chassis_node --ros-args -p bus_type:=socketcan -p channel:=can0 -p initial_enable:=false'
```

预期：节点日志显示连接 `socketcan/can0`；`0x100` 维持 100 Hz，VX/VY/WZ 为零且 enable 位为零。命令超时结束后节点正常退出。

- [ ] **Step 3：同时核对总线与 ROS 反馈**

节点运行期间，并行监听 `0x100`、`0x200`、`0x230`：

```bash
ssh orin 'timeout --preserve-status --signal=INT 15s candump -L can0,100:7FF,200:7FF,230:7FF'
```

同时运行一次性 ROS 订阅：

```bash
ssh orin 'source /opt/ros/jazzy/setup.bash && timeout --preserve-status --signal=INT 15s ros2 topic echo --once /chassis/measured_twist'
```

预期：监听到 Orin 的禁用零速 `0x100`，并收到下位机 `0x200`/`0x230`；ROS 收到 `/chassis/measured_twist` 的零速反馈。

- [ ] **Step 4：检查联测后的总线错误计数**

运行：`ssh orin 'ip -details -statistics link show can0'`

预期：接口仍为 UP，bus-off、RX/TX error 没有增长。协议没有命令回执字段，因此本轮结论限于物理 CAN 双向收发、帧解码和 ROS 反馈，不声称验证了运动指令执行。

## 安全门槛

- 本轮不得调用上位机 `~/safety_cmd`，不得发送 `0x010 START`，不得将 `0x100` 的 enable 位置 1，不得发送非零速度。
- 若底盘没有发出 `0x200`/`0x230`，不得假定它已运行 R21。烧录须等用户另行确认，并先确认轮子架空、动力端隔离及 PC6 舵机扫动的机械安全。
- 本轮不提交或推送 Git。提交或部署需要用户明确要求。
- 发现帧错误、bus-off、错误计数增长、节点身份异常或底盘动作时，立即结束节点并停止联测。
