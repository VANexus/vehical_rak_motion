# USB v2 与 ROS 2 控制链路设计方案

- 日期：2026-10-06
- 状态：设计已获用户批准，待方案书审阅
- 范围：C30D F407 底盘、Jetson Orin 上的 USB v2 轮端链路，以及 Nav2/ros2_control/MoveIt2 的控制边界

## 1. 目标

以 USB Serial Protocol v2 作为 Jetson 与 F407 之间唯一的实时控制协议，落实 ADR-0007 的上位机麦轮逆运动学与统一 `ros2_control` 架构。本轮优先完成轮端 v2 端点和 Nav2 到四轮控制器的链路；v2 的 ARM 协议端点一并实现以满足完整能力协商，但机械臂保持未 commissioned、不可使能，MoveIt2 仅用于仿真。

本方案不启用 CAN v3，不实现实机机械臂运动，不以协议回显冒充传感器反馈，也不把未标定的运动学参数投入实车导航。

## 2. 现状与依据

- Orin 已枚举底盘的 WCH CDC 串口：`/dev/serial/by-id/usb-WCH.CN_USB_Single_Serial_0004-if00`，对应 `/dev/ttyACM1`；同一时刻未发现底盘串口驱动进程占用设备。
- F407 R21 仍运行 UART v1 endpoint；`Core/Src/app_protocol_v2.c` 已编入固件，但目前只是独立 codec，没有接入 `app_serial.c`、控制环或遥测。
- `rak` 有独立的 Python v2 codec 和测试；v1 `BaseUartNode` 仍使用机体速度协议。仓库中尚无 C++ `ros2_control` `SystemInterface` 硬件插件。
- Nav2 使用 MPPI `motion_model: Omni`，已有速度平滑和 Collision Monitor；尚未接入 `mecanum_drive_controller`。
- MoveIt2 六轴配置是仿真夹具；当前没有已签核的实机关节名称映射、方向、零位、限位、速度限制或位置传感器。
- 上位机 `rak` 工作树包含大量用户未提交改动。实施时只改方案明确列出的文件，逐个检查目标文件差异，不覆盖或清理其他改动。

## 3. 总体架构

```text
Nav2 MPPI Omni
    │ geometry_msgs/Twist
速度平滑 → Collision Monitor → TwistStamped 类型适配
    │
mecanum_drive_controller（上位机麦轮逆运动学）
    │ 四轮 velocity command/state interface
rak_hardware（C++ SystemInterface，USB 唯一所有者）
    │ USB CDC/USB-UART，COBS + CRC16，协议 v2
F407 v2 endpoint
    ├─ 四轮速度目标 → IMU 轮级稳定补偿 → 等比饱和 → 现有 25 kHz 轮速闭环
    ├─ 编码器反馈、采样时间、有效位与 encoder epoch
    └─ ARM v2 帧解析与状态格式；commissioning 未完成时拒绝 ARM 输出

MoveIt2 → 六轴仿真模型与 fake controllers
         └─ 本轮不连接 rak_hardware，不发送实机关节目标
```

Nav2 的 MPPI Omni 继续负责机体速度规划；麦轮 IK 由 `mecanum_drive_controller` 负责。Nav2 的仿真、桩和硬件末端适配必须互斥，硬件路径只保留一个最终速度命令所有者。

## 4. 协议与 F407 设计

### 4.1 完整 v2 合同

- 保留 `docs/protocol/usb_serial_v2.md` 的协议版本、COBS 定界、CRC-16/CCITT-FALSE、独立序号、严格 payload 长度、HELLO 协商、时间同步、诊断、安全命令及 10–200 ms 独立 lease。
- required feature 0/1/2 继续全部必需：四轮速度命令、六轴位置命令端点、轮编码器里程计。不得通过降低 feature 要求或静默回退 v1 来让握手通过。
- ARM endpoint 按 v2 实现并报告能力；feature 能力不等于物理使能许可。六轴安装映射和限位未签核前，F407 对 ARMED ARM 命令保持拒绝/锁闭；ARM 状态维持 DISARMED，测量有效位清零、测量来源为 unavailable。MoveIt2 不连接实机接口。
- 不声明没有硬件依据的功能：机械臂实测位置 feature、夹爪第七轴、板载温度或其他未实现传感器能力均保持关闭。
- v1 与 v2 不自动协商降级；USB 物理链路只由一个上位机进程持有。

### 4.2 轮端控制与反馈

- DRIVE_COMMAND 的四轮顺序固定为前左、前右、后左、后右，单位为 rad/s；在任务上下文用定点整数换算成 MCU 原生 counts/ms，不在 25 kHz ISR 中做浮点或复杂除法。
- F407 必须保留板载 IMU 的轮级稳定/滑移补偿职责。当前 `app_car.c` 的 `stabilizer_apply()` 会在 MCU 侧改写机体 `wz`，并包含旋转指令释放后的航向保持；这段实现不能原样接到 v2 轮速入口。
- v2 下将稳定补偿重构到四轮目标域：根据 IMU 与编码器反馈生成有界轮级修正，再对最终四轮目标应用同一个饱和比例；不得逐轮独立截断。轮级补偿不能生成或争用上位机的 body-yaw 目标，也不能在 Nav2 请求零偏航时隐式保持机体航向。
- 轮级补偿的分配矩阵、滤波、增益和限值需要单独台架验证；在确认稳定、有限且不抵消 Nav2 yaw 命令前，不进入 ARMED 运动测试。25 kHz ISR 与单写者规则保持不变，IMU 与补偿计算留在任务上下文。
- DRIVE_STATE 必须来自编码器采样：轮位、轮速、采样时刻、valid mask 与 encoder epoch 分开表达。无效或过期数据不得伪造为零速有效反馈。
- drive 与 arm 使用独立 lease；CRC、序号、长度或模式非法的帧不得刷新 lease。复位、重连和 lease 失效均保持 DISARMED。
- v2 构建关闭当前 PC6 上电自检扫动。若保留该诊断能力，只能通过明确的诊断入口显式触发，默认启动不输出舵机扫动。

## 5. 上位机与 ROS 2 设计

### 5.1 `rak_hardware`

- 新增 C++ `hardware_interface::SystemInterface` 插件，作为 USB 串口唯一所有者；使用稳定设备路径，不依赖 `/dev/ttyUSB0` 或可变编号。
- `read()`/`write()` 不做阻塞串口等待或无界分配；传输线程处理 USB 收发，控制循环通过有界缓冲交换最新命令与最新有效反馈。
- 本轮 hardware configuration 只导出四个轮关节的 velocity command、position/velocity state。ARM v2 frame/state codec 可存在于传输层，但不向 MoveIt2 暴露实机关节 command interface。
- 硬件默认关闭、启动与重新连接均 DISARMED；controller lifecycle 激活不等同于 actuator ARM。ARM/drive 使能必须有独立显式安全许可。
- 串口断开、boot ID 变化、过期状态、无效反馈、非零故障或序号不前进时撤销使能并写零目标；恢复通信不得自动重新使能。

### 5.2 麦轮控制与 Nav2

- 使用 Jazzy `mecanum_drive_controller` 作为标准麦轮 IK 与轮关节控制器，配合 `joint_state_broadcaster` 和 `controller_manager`。
- 显式配置 wheel radius、机器人中心在 X/Y 的投影和、`reference_timeout`、控制器周期及 `enable_odom_tf: false`。所有实机几何、方向、速度/加速度限制均须来源于测量；缺失时硬件 bringup 应保持关闭或拒绝配置。
- Nav2 保留 MPPI `Omni` 模型、速度平滑和 Collision Monitor；在最终命令末端完成 `Twist` 到控制器所需 stamped reference 的适配，并保证只有一个最终发布者。
- 初始定位阶段保留 rf2o 作为唯一 `odom → base_link` TF 发布者。mecanum controller 的轮里程计使用独立 topic，未标定前不进入 EKF。接入 `robot_localization` 前，必须先具备可信采样时间、协方差和 IMU 数据，并确保 rf2o 不再重复发布该 TF。
- Nav2 的硬件模式、仿真模式和桩模式互斥；仿真默认不变。没有有效轮参数或新鲜反馈时不得将硬件链路宣称为导航可用。

### 5.3 MoveIt2

- 本轮仅审查和维护独立的六轴仿真模型、SRDF、KDL/OMPL 配置与 fake controllers；明确标记虚拟几何和限位仅供仿真。
- 不使用旧五轴 `rak.urdf.xacro` 或 `six_axis_sim` 的占位尺寸/限位作为实机描述，不把命令回显当成实测关节位置，不将 MoveIt trajectory execution 接到实机串口。
- 实机关节控制另设后续阶段：取得关节顺序、方向、零位、限位、速度/加速度、PWM 映射及安全保持方式签核；无位置传感器时必须明确执行完成语义，不能声称实测跟踪成功。

## 6. 分阶段交付

### 阶段 A：v2 endpoint 与协议一致性

- F407 接入 v2 收发、完整 required feature 协商、轮/ARM 帧校验、序号、独立 lease、安全状态和诊断。
- 迁移板载 IMU 稳定逻辑到四轮目标域，验证其输出有界、饱和后比例一致，且不会建立与 Nav2 冲突的机体航向目标。
- host codec 与 F407 codec 使用相同 golden vectors；PTY peer 覆盖握手、错 CRC、旧序号、重连、lease 与 DISARMED 状态。
- 下位机构建 tag 升为 R22；不改 `.ioc`，除非实现中证明确有外设配置缺口并单独按 CubeMX SOP 审批。

### 阶段 B：上位机硬件接口与 Nav2 控制链

- 新建 C++ `rak_hardware`，以 PTY 模拟 F407 验证 controller lifecycle、四轮命令、状态有效性、超时和重连闭锁。
- 接入 `mecanum_drive_controller` 和 Nav2 stamped reference 末端；仿真、桩、硬件模式单写者验证。
- wheel radius、轮间距/投影和、encoder conversion、轮符号及速度限制未签核时，只做仿真和接口测试，不允许 ARM。

### 阶段 C：MoveIt2 仿真隔离与配置验收

- 验证规划组、joint limits、kinematics solver、fake controller 和 launch 互不依赖 hardware mode。
- 证明启动 MoveIt2 仿真不会打开 USB、启动 F407 控制器或发送 ARM_COMMAND。
- 本阶段不验收实机关节动作。

### 阶段 D：DISARMED USB 实机验收

- 烧录前核对 R22 镜像、轮子架空、动力隔离及舵机自检扫动已关闭；烧录后按仓库要求真断电冷启动并核对 OLED build tag。
- 使用稳定 WCH 设备路径运行一个硬件进程，完成 HELLO/HELLO_ACK、所需 feature、DRIVE_STATE、ARM_STATE DISARMED 状态和诊断帧验证。
- 只发送 DISARMED 零目标；不发 ARMED 轮速、不发 ARMED 关节目标、不调用运动接口。检查序号、CRC、encoder epoch、数据年龄、lease 和错误计数。
- 任何错误帧、状态不一致、反馈失效或执行器动作都立即停止联测，不宣称通过。

电机点动、Nav2 实车行驶和 MoveIt2 实机关节执行均不属于本次 DISARMED 通信验收；它们需要独立的标定、机械安全检查和明确的运动授权。

## 7. 最佳实践与安全约束

- 麦轮 IK 在上位机标准 `mecanum_drive_controller`，轮级等比饱和留在 MCU，避免上位机轮限幅改变机体运动方向。
- 25 kHz ISR 不加入协议解析、USB 操作、浮点、阻塞或日志；协议、换算、租约和状态组包运行在任务上下文。
- CAN v3 不参与 USB v2 控制；严禁同时启动旧 v1 `BaseUartNode`、`rak_serial_link` 或 CAN 节点占用同一设备。
- `ros2_control` controller active、Nav2 lifecycle active、MoveIt planning success 均不等于硬件获得运动许可。
- 只读反馈必须标记有效性、采样时刻与数据年龄；没有测量能力不得用命令目标填充反馈状态。
- 不修改 25 kHz 频率，不把仿真参数当作实测参数，不自动提交或覆盖上位机现有未提交改动。

## 8. 明确不做

- 不实现或启用 CAN v3 控制。
- 不开放 ARM 实机使能、夹爪第七轴或实机关节轨迹执行。
- 不以 wheel odometry 替代有效 EKF/TF 配置，也不将未标定数据接入导航。
- 不在本设计阶段发非零速度、ARMED 命令或实车点动。
- 不更改已有上位机用户改动；不做无关重构或自动 Git 提交。
