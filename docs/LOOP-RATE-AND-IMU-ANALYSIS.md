# 底盘闭环频率 / 板载 IMU 频率 —— 能不能"拉很高"？

> 2026-10-28 写。**结论先行**：CPU 有富余（但**占用率尚未实测**，见 §1.3）；
> **"把频率拉高"对轮子的收益很小**，真正卡住精度的是 PWM 频率（AT8236 消隐时间）、
> 编码器量化（M 法测速）和机械；**板载 IMU 拉高速同样不划算**，而且它本来就不是
> 权威 IMU（权威源在 Jetson 的 LSM6DSRTR）。
> 本文事实分三级标注：**[实测]** / **[读码]** / **[推断]**；规格类给出资料包内出处。

## 1. 现状（读码，2026-10-28）

### 1.1 三个"频率"不是一个东西，先分清

| 频率 | 当前值 | 出处 |
| --- | --- | --- |
| **PWM 载波**（AT8236 开关频率） | **25 kHz**（TIM1/9/10/11，`Period=6719`@168 MHz） | `Core/Src/tim.c` [读码] |
| **闭环 ISR**（TIM6 中断，编码器采样 + 刷 PWM） | **25 kHz**（`Period=3359`@84 MHz） | `app_car.c` `car_control_isr()` [读码] |
| **速度环 / PI**（M 法测速 + 定点 PI） | **1 kHz**（ISR 每 25 拍做一次） | `app_car.c`：`if (++win_cnt >= 25U)` [读码] |
| 轮速遥测 EMA | α=1/16 → τ≈16 ms @1 kHz | `app_car.c` R39 注释 [读码] |
| 监督器（自检/IK/遥控/安全链/IMU） | **100 Hz** | `Task_Control` [读码] |

**关键**：25 kHz 的 ISR 里，**每 40 µs 只做"读码器 + 刷 PWM"**；测速与 PI 是 1 ms 一次。
所以"拉高 ISR 频率"和"拉高控制频率"是两件事，收益/代价完全不同。

### 1.2 编码器量化把"缩短窗口"这条路堵死了

- 编码器：电机侧、硬件正交 ×4，**61 440 计数/输出轴圈**（标称；A 路手转实测 ≈61 602，[转述·待复测]）。
- 代码注释实测口径：**巡航时一个 40 µs 窗只有约 6 个计数**（`app_car.c` 头注释 [读码]），
  所以刻意用 **1 ms 窗**做 M 法——`1 ms 窗 = 150 计数`（BENCH_CRUISE=150 counts/ms）。

| 测速窗 | 巡航时窗内计数 | ±1 计数带来的相对误差 |
| --- | --- | --- |
| 40 µs | ≈6 | **≈17 %** ← 这就是当初放弃它的原因 |
| **1 ms（现状）** | **≈150** | **≈0.7 %** |
| 0.5 ms | ≈75 | ≈1.3 % |
| 0.2 ms | ≈30 | ≈3.3 % |

⇒ **把 ISR 提到 50 kHz（20 µs）不会提高测速精度**；反倒有人会顺手把窗口也缩短，那是**变差**。
要"超精细"：**窗口可以再拉长**（2–5 ms，误差 ∝ 1/计数），或用 **T 法/位置差分+观测器**，
而不是提高 ISR 频率。

> 注：`V_CMD_LIMIT = 350 counts/ms` 是内部安全钳位（不是额定巡航值）。

### 1.3 CPU 占用率：**还没实测过**

- 168 MHz → 40 µs = **6720 周期**；`AGENTS.md` 要求 ISR 占用 **≤ 35 %（=2352 周期）**，
  且"没实测数据不算完成"。
- 代码里**已经埋好**量具：`dbg_isr_last_cycles` / `dbg_isr_max_cycles`（`app_car.c` R19，DWT 周期计数，
  SWD 直读）。**但目前仓库里查不到任何实测值** → 这是一个**未完成的验收项**。
- [推断] ISR 主体很轻（4 次 `CNT` 读 + 加减、每 25 拍一次除法常量 PI、4 次写 CCR），
  量级应在**几百周期**（≈几个百分点）。**但这只是推断，上板必须实测后再谈"还有多少余量"。**
- ⚠️ 现有量法只量了"清 UIF 之后到返回"，**不含 NVIC 入/出栈**；要严谨应再加"翻转 GPIO + 逻辑分析仪"对照。

### 1.4 反倒有一个**反向**的风险没关掉

`docs/PROTOCOL.md` §7.1 与 `AGENTS.md` §4 都记着一条**台架记录：只有 10 kHz 才出额定扭矩**
（与 25 kHz 设计冲突）。这条至今**没有复测结论**。**在这种背景下谈"把 PWM 频率再拉高"是南辕北辙**：
频率越高，单次导通时间越短、开关损耗越大。

### 1.5 AT8236 给了硬上限（2026-10-28 读规格，出处见 `BOARD-C30D.md` §1）

- **逻辑输入 PWM 频率 fPWM 上限 = 100 kHz** ⇒ 频率本身不是瓶颈；
- **消隐时间 tBLANK = 2.2 µs（典型）**，它**同时决定"电流衰减时的最小 PWM 导通时间"**：

| PWM 载波 | 周期 | 最小可用占空比 = 2.2 µs / 周期 |
| --- | --- | --- |
| 10 kHz | 100 µs | 2.2 % |
| **25 kHz（现状）** | **40 µs** | **5.5 %** |
| 50 kHz | 20 µs | **11 %** |
| 100 kHz | 10 µs | 22 % |

⇒ **PWM 频率越高，低速微调的分辨能力越差**（占空比低于 2.2 µs 的脉冲直接不输出）。
再叠加"起步静摩擦要 ~75 % 占空比"（[转述·待复测]），本车的**有效占空比区间本就只有 75–85 %**，
把载波拉到 50 kHz 等于把可用区间进一步压缩。

## 2. 建议

1. **PWM 载波保持 25 kHz**（先复测 25 kHz 能否出额定扭矩这条风险，再谈别的）。
2. **ISR 保持 25 kHz**；先把 `dbg_isr_max_cycles` 实测出来（一行 SWD 读），
   有数据再决定要不要降/升。
3. 想要"精细"，改这三样而不是频率：
   - **测速窗口 1 ms → 2–5 ms**（误差线性下降），代价是相位滞后 → 只在低速/精细模式下用；
   - 或加 **T 法/位置差分**通道，低速时切过去；
   - 控制律升级（前馈/观测器）——收益远大于提高采样率。
4. 如果确实要动 ISR 频率，**只改 `MX_TIM6_Init` 的 ARR**（CubeMX 里改），
   且必须重测占用率；**不要顺手缩短测速窗**。

## 3. 板载 IMU 能不能拉高？（板载 = PB10/PB11 那颗）

**先弄清"板载 IMU"指哪一个**（`BOARD-C30D.md` §3）：

| IMU | 接到哪 | 驱动/总线 | 固件用途 |
| --- | --- | --- | --- |
| **ICM-20948 / MPU-6050**（两块板型号不同，自动探测） | **MCU（PB10/PB11）** | **软件 I²C**（bit-bang，开漏+外部上拉） | 只取陀螺 Z 轴，供**本地**自稳定环 |
| **LSM6DSRTR** | **Jetson**（不经 MCU） | Jetson 侧驱动 | **权威 IMU / 融合在 Jetson** |

⇒ 用户说的"板载 IMU"= **MCU 侧那颗陀螺**。它**不是**权威源。

### 3.1 三道硬限制（读码）

1. **芯片输出率**：`app_imu.c` 现配 `SMPLRT_DIV` 是 **ICM≈140 Hz / MPU≈125 Hz**（注释原文）。
   也就是说**芯片本身每秒只产出 125–140 个新样本**——你读得再快也是重复读数。
   想更高得改 ODR（ICM-20948 陀螺最高 1125 Hz；MPU6050 最高 1 kHz/8 kHz），
   代价是必须相应放宽 DLPF（现 DLPF 44 Hz 带宽）→ 噪声变大。
2. **软 I²C 是阻塞的**：一次"写寄存器地址 + 读 2 字节"≈ 3 字节 × 9 位 ≈ 27 个位时。
   `ICM_I2C_DLY=120`（半周期忙等）[读码] → 单次读约 **百微秒量级**；**EMI 下还要重试**。
   - 100 Hz 读：占用 ≈1–2 % CPU（现状，可以忽略）；
   - 1 kHz 读：**约 15 % CPU**，且全在 100 Hz 任务里**阻塞**，会挤掉别的任务。
3. **总线/EMI**：软 I²C 就在电机动力线旁边，驱动注释明说"电机运行时受 EMI 干扰"。
   频率越高，撞上 EMI 的概率越高。

### 3.2 结论

- **不建议**把 MCU 侧陀螺拉到很高：芯片 ODR 封顶 125–140 Hz 是**硬顶**，
  往上要么改 ODR + 降 DLPF（更噪），要么花 15 % CPU 去读重复样本。
- 真要提高姿态频率/质量，正确做法是**用权威 IMU（Jetson 侧 LSM6DSRTR）**，
  或把板载 ICM 改成**硬件 I²C/SPI + DMA**（这要动 .ioc/改板，属另一轮）。
- 若只想让**本地阻尼**更跟手：把 100 Hz 提到 **400–500 Hz**（芯片 ODR 之下）即可，
  占用仍 <10 %，是性价比最高的档位。

## 4. 一句话回答

- **轮子**：CPU 有余量（**但占用率要先实测**），不过**提高频率买不到精度**——
  精度被 PWM 消隐时间（2.2 µs）、编码器量化（40 µs 窗仅 ~6 计数）和机械限住。
  要精细就**拉长测速窗 / 上 T 法 / 改控制律**。
- **IMU**：芯片 ODR 125–140 Hz 是硬顶，软 I²C 又阻塞又怕 EMI；**拉高不划算**，
  真正该拉高的是 Jetson 侧的 LSM6DSRTR。
